# Known Issues, Limitations and Risks

| ID | Type | Description | Status | Workaround / plan |
|---|---|---|---|---|
| KI-001 | Technical risk | Firebase under `file://` is unproven. Concerns to validate: (a) the modular Firebase SDK ships as ES modules, which browsers block from `file://`, so the classic-script "compat" builds would be needed; (b) Firebase Auth behaviour and API-key restrictions with a `null`/`file://` origin; (c) IndexedDB-based offline persistence varies by browser under `file://`; (d) Firestore network calls from a `null` origin. | Open | Phase 0 spike (TQ-1). If it fails, present alternatives before proceeding. |
| KI-002 | Security limitation | A `file://` app has no server; all code is visible to anyone with the folder. Security must rest on Firebase Auth + Firestore Security Rules, never on hidden pages or localStorage flags. | Accepted constraint | Design security rules as the real boundary. |
| KI-003 | Security limitation | Cross-document business rules (stock vs movements, balances) are enforced by client transactions; Security Rules validate per-document shape/invariants only. Acceptable for a single trusted owner. | Accepted for v1 (pending AQ-3) | Revisit Cloud Functions (Blaze plan) before adding staff accounts. |
| KI-004 | Privacy trade-off | Username login needs a pre-login lookup `usernames/{username}` → email. Anyone who knows or guesses the exact username can read the recovery email (listing is denied). | Pending AQ-2 | Use a non-obvious username; or switch to email login. |
| KI-005 | Technical limitation | Restore is written in batches of up to 500 documents, so it is not one atomic operation; an interrupted restore may be partial. | Accepted | Restore only into an empty database or after "replace all" confirmation; restore can be re-run idempotently (same document IDs). |
| KI-006 | Platform limitation | Phones cannot run a local `index.html` folder reliably (iOS not at all). | Pending D-014 / AQ-1 | Publish the same build to Firebase Hosting for phone access. |
| KI-007 | Dependency risk | Firebase compat builds may be removed in a future major SDK version. | Open | Pin a version that ships compat builds; vendored copy keeps working regardless. |
